# V2 分阶段实施计划

## 阶段 0：契约和边界

- 固定规范主体、产品、外部映射和原始证据契约；
- 确认内部 ID、状态、合并和审计规则；
- 不连接 8000 生产数据库，不执行生产数据迁移。

验收：契约文档可独立评审，所有后续模块都能映射到规范 ID。

## 阶段 1：最小可运行底座

- 新项目配置、健康检查、数据库迁移框架；
- 认证、权限、审计日志的最小实现（当前已完成单 API Key 角色门禁和系统审计，用户中心与细粒度权限仍待实现）；
- `parties`、`party_roles`、`external_bindings`、`source_records`、`products` 的第一版模型；
- 规范化、匹配、待审核和幂等测试。

验收：本地可启动；迁移、创建、查询、匹配和重复导入测试通过；没有旧系统运行依赖。

## 阶段 2：主数据工作台

- 客户/公司/供应商统一搜索和详情；
- 产品统一搜索、规格和来源映射；
- 合并审核、停用、恢复和审计；
- 只读展示来源证据，不让业务页面直接修改原始证据。

验收：从任一业务入口进入同一主体或产品，都回到同一个规范 ID。

## 阶段 3：一个完整业务切片

先选一个边界清楚的流程，例如“采购导入 → 产品匹配 → 入库事实 → 库存余额”。

- 接入一个来源；
- 原始证据、规范映射、业务事实全链路可追溯；
- 与旧系统结果做只读对比；
- 暂不替换旧系统写入。

验收：真实样本通过数量、金额、产品和来源链路核对。

## 阶段 4：逐步接入其他模块

按采购、销售、库存、财务、物流和外部平台逐块接入。每一块只能引用 V2 规范主档，不能再引入自己的客户/公司/产品表。

验收：模块级双读或影子运行结果一致，异常可以回滚到旧流程。

## 阶段 5：切换和退役

- 完成数据覆盖报告和差异确认；
- 先切换读，再切换写；
- 保留旧系统和原始数据作为回滚边界；
- 稳定运行后再决定是否退役旧模块。

每个阶段只做一批可验证改动，避免一次性重写整个生产系统。
